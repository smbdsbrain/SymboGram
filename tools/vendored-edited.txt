# Vendored files SymboGram has deliberately edited, and why.
#
# docs/VENDORED.md says "no remaining file has been edited". That is true of
# mbedtls, zlib, qt-json, pigler and tl-generator -- and it was never true of
# libkg/, which is a fork, not a pinned dependency: the rename to SymboGram
# and the Symbian build fixes land in it by definition. Recording the edits
# here rather than leaving the claim overbroad is also how the GPL-3.0
# "state what you changed" obligation stops being prose and starts being
# checkable: tools/verify-vendored.py --online fails on any edit NOT listed
# below, so a new one cannot pass unnoticed.
#
# Format: one path per line. Comments and blank lines ignored.
# Line-ending-only differences are reported separately and never count as
# edits -- libkg/ was renormalised to CRLF during the rename.

# --- libkg: test-environment plumbing ---
# tgtransport.{h,cpp}  testMode was a hardcoded false with the comment "change
#                      it for debugging or whatever". It is a constructor
#                      argument now, so one binary can reach both environments;
#                      the e2e harness needs that and recompiling to switch DCs
#                      let the two paths drift apart unnoticed.
# tgclient.{h,cpp}     carries the flag and, critically, passes it into the
#                      children getClientForDc() creates -- a child without it
#                      would open a PRODUCTION connection holding a TEST auth
#                      key, which presents as a codec bug.
libkg/tgtransport.h
libkg/tgclient.h

# --- libkg: not a rename ---
# crypto.cpp  the entropy personalisation string. mbedtls_ctr_drbg_seed is
#             called with a hardcoded length of 20, so the replacement had to
#             be exactly 20 bytes; "symbogram_random_lol_" would have been 21
#             and silently truncated. A comment now records that constraint.
libkg/crypto.cpp

# --- libkg: inbound MTProto verification ---
# tgtransport.{h,cpp}  processMessage decrypted a packet and parsed it without
#                      checking auth_key_id, msg_key, session_id, msg_id or the
#                      declared body length. msg_key verification is the whole
#                      of MTProto 2.0's integrity guarantee, and without it the
#                      generated readers -- a switch with no default: case --
#                      dispatch on bytes chosen by whoever can write to the
#                      socket. Also the seq_no accounting and the ack path.
# crypto.{h,cpp}       calcMessageKey takes the direction it derives from: the
#                      two read different 32-byte fragments of the auth key and
#                      it had only the outbound one, so it could not verify
#                      anything. decryptAES256IGE no longer returns an
#                      uninitialised buffer when mbedtls refuses the input.
# tgstream.{h,cpp}     readFully sized its buffer from a signed length prefix
#                      taken off the wire, with no upper bound.
libkg/crypto.h
libkg/tgstream.h
libkg/tgstream.cpp

# --- libkg: reconnect, updates and the local cache ---
# tgtransport.{h,cpp}  reconnect policy lived in QML and retried at the speed
#                      of the event loop. The transport now backs off, times
#                      out a connect that never completes, and reports one drop
#                      once instead of two or three times.
# tgclient.{h,cpp}     owns the update pipeline and the cache, and routes every
#                      Updates constructor through the former.
# libkg.pri            lists the new translation units below.
#
#
# New files, first-party rather than upstream's. Adding one to a fork is a
# change the same obligation covers, so they are declared here too:

#                         channel polling.
# tgc_updates.cpp         updates.getState / getDifference / getChannelDifference,
#                         following the tgc_<namespace>.cpp convention.
# tgstore.{h,cpp}         the optional SQLite cache.

# --- libkg: the SRP password proof ---
# crypto.{h,cpp}  SHA-512, HMAC-SHA512 and PBKDF2-HMAC-SHA512. The vendored
#                 mbedtls has MBEDTLS_PKCS5_C disabled in its pinned config,
#                 so mbedtls_pkcs5_pbkdf2_hmac_ext compiles to nothing; the
#                 derivation is written here over mbedtls_md_hmac_* rather
#                 than by editing the pin, which would put a local change
#                 inside a tree whose whole value is being byte-identical.
#                 Also Pbkdf2Sink, so a derivation the user has abandoned
#                 stops instead of holding the password to completion.
#
# New files, first-party:
# srp.{h,cpp}     Telegram's SRP-6a proof for auth.checkPassword. Separate
#                 from crypto.cpp because it carries a protocol failure
#                 reason rather than a primitive, and because tests/crypto
#                 links it without libkg.pri and therefore without any
#                 credentials.
# tgsrpworker.{h,cpp}  runs the proof off the GUI thread. The derivation is
#                 seconds on the target hardware, and the modular
#                 exponentiations are atomic inside mbedtls, so there is no
#                 chunking that keeps the interface responsive.
# tgc_password.cpp  the flow -- account.getPassword, the proof, then
#                 auth.checkPassword -- following the tgc_<area>.cpp
#                 convention. Driven from the client rather than from QML so
#                 that every attempt uses freshly fetched parameters.
libkg/srp.h
libkg/srp.cpp
libkg/tgsrpworker.h
libkg/tgsrpworker.cpp
libkg/tgc_password.cpp

# --- libkg: message operations ---
# tgc_messages.cpp  messages.deleteMessages, readHistory and editMessage, plus
#                 reply_to on sendMessage. The reply_to key is inserted only
#                 when there is an id: the generated writer computes flags from
#                 which keys are present, so an empty map sets the bit and then
#                 writes nothing for it.
# tgclient.{h,cpp}  the new methods, an InputChannel helper, and the
#                 messages.AffectedMessages case -- whose pts reaches the
#                 update pipeline before the reply reaches anyone else.
# tgupdates.{h,cpp}  applies a pts that arrives in a reply. Nothing pushes
#                 that change back, so without it the local sequence falls
#                 behind and the next pushed update reads as a gap.
# tgc_utils.cpp   toInputChannel, beside the other peer helpers.
#
# New file, first-party:
# tgc_channels.cpp  channels.deleteMessages and channels.readHistory. They take
#                 an InputChannel rather than an InputPeer, and their
#                 messages.* counterparts do not reach a channel at all.
libkg/tgc_channels.cpp
